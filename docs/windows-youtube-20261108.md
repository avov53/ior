# Windows 10/11: подписки, кнопки и проверка YouTube — тестовая 1.2.6

## Подтверждено журналом

Автообновление сработало при запуске. Записи `+1, updated 2, removed 1` означают обработку трёх записей, а не одного VLESS. По этим строкам нельзя установить, какой именно протокол получил новый ID. При обновлении теперь выводятся итоговое количество и распределение по протоколам.

Для единственного AWG-пира с прежними ключами и endpoint смена служебных AWG-параметров сохраняет ID записи, выбор, пинг и сведения о стране. При смене ключей или неоднозначности нескольких пиров такая подстановка не выполняется. Работающее подключение не перезапускается: новые параметры используются при следующем подключении.

Кнопки пинга, обновления и информации объединены в один правый flex-контейнер с промежутком 4px. Проверены DOM и снимок локального макета Edge с вымышленной подпиской; это не запуск рабочего приложения пользователя.

## Ограниченный резерв AWG для Windows 10

Журнал содержит отказы `AWG_PROXY_FAMILY_REJECTED` для IPv6 при IPv4-туннеле. До изменения неподдерживаемый пакетный путь мог отвергнуть TCP до обработки имени приложения. Тестовая сборка передаёт такой TCP-поток существующему стеку разбора имени, не создавая параллельный raw AWG-поток. При известном имени используется IPv4 через тот же AWG; исходное решение PROXY сохраняется. Неизвестные имена, чистые IPv6-литералы и неподдерживаемый UDP не маскируются под успешное подключение. DIRECT и REJECT не переводятся в PROXY и наоборот.

Функция включается только Windows 10-хостом для AWG и только при совпадении SHA-256 бинарника с `core/ior-core/awg-named-ipv4.sha256`. Для старого ядра новый параметр не передаётся. При собственном пути к другому ядру резерв может остаться выключенным; настройки пути автоматически не переписываются. Windows 11 сохраняет прежний закреплённый бинарник. Android не меняется.

Отказы отдельных пакетов неподдерживаемой семьи при готовом VPN обозначаются предупреждениями. Ошибка определения страны — предупреждение вспомогательной функции. Ошибки запуска, петли и восстановления остаются ошибками.

## Что ещё не доказано

HTTP 403 у `videoplayback` сохранился у пользователя после повторного открытия видео. Это ответ сервера; без проверки конкретного запроса нельзя считать причиной только туннель, DNS, смену IP или открытый ранее плеер. Исправление AWG не объявляется решением HTTP 403 на Hysteria.

После отдельного разрешения пользователя выполнены ограниченные SOCKS-пробы на Windows 11 build 26300 с уже включённым Hysteria VPN. YouTube `generate_204` ответил 204, корень сервера изображений — 400, корень redirector.googlevideo.com — 404, Cloudflare — 200. Старый и новый бинарники дали те же статусы и одинаковый отпечаток выходного IP. Корневые 400/404 не являются проверкой конкретного аватара или подписанного video URL; HTTP 403 видео этим не воспроизведён.

AWG в изолированном SOCKS-режиме не проверяется: оба бинарника требуют TUN (`AWG_TUN_REQUIRED`). Первые попытки получили закрытие канала до подключения; это ограничение режима тестового стенда, а не доказательство нового сбоя рабочего AWG. Второй системный TUN не создавался. Таблица маршрутов, DNS, эффективные NRPT-политики и ранее работавшие процессы ior/xray совпали до и после проверок. Это не испытание проблемного Windows 10. Тестовый токен VpnFake не используется.

## Проверки и передача

- 460 тестов .NET прошли; opt-in сетевой тест без переменных окружения не выполняет подключения.
- Rust: 156 пройдено, 12 opt-in пропущено. Проверены отсутствие второго raw-пути, сохранение PROXY-правила, отказ литералам, отключённый резерв и прежний UDP-путь.
- Локальный стенд без пользовательских конфигов: по 3 запуска старого/нового ядра. Медианы запуска 28,90/26,73 мс, передачи 4 МиБ — 52,31/41,89 мс. Это короткие loopback-измерения, не доказательство ускорения YouTube или реального AWG.
- Рабочие пакеты, текущий dist, Android и GitHub сохраняются. Новый протокол пока не реализуется.

Распаковать нужный Windows-пакет отдельно, закрыв прежний ior. На Windows 10 проверить AWG: открыть YouTube заново и проверить аватары. Затем проверить Hysteria; при повторном 403 сохранить статус, имя хоста и текст ошибки без токенов, cookies и полного подписанного URL. При отметке «Проблема с интернетом» экспортировать соответствующий диагностический ZIP. Проверка реального Windows 10 и реального браузерного сценария необходима до объявления проблемы устранённой.
