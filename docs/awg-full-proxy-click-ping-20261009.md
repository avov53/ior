# AWG FullProxy и пинг по клику — 9 октября 2026

Статус: экспериментальный кандидат. Ускорение YouTube/Discord, перемотки и 4K
на скорости 2× на пользовательском сервере ещё не подтверждено.

## Изменения

- В настройках → Дополнительно добавлена «Маршрутизация AmneziaWG»:
  `Rules` («По выбранным правилам», по умолчанию) и `FullProxy`
  («Весь трафик через AWG»). Изменение применяется при следующем подключении.
- FullProxy действует только для AWG + ior-core + TUN. В runtime создаётся
  единственный MATCH → PROXY; сохранённые маршруты/профили не переписываются.
  В этом режиме выбранные DIRECT/REJECT-правила не применяются; UI предупреждает
  об этом рядом с переключателем. В остальных протоколах настройка не действует.
- Сохранены физический выход к VPN-серверу, проверка HTTPS/PROXY, локальный
  DNS TUN и откат. Семейства адресов и AllowedIPs профиля проверяются; нет
  скрытого DIRECT при несовместимости. DNS, MTU, ключи и обфускация не менялись.
- Фактический режим передаётся как необязательный `options.awgRoutingMode`
  (`rules`/`fullProxy`) и записывается в журнал. Rust отклоняет FullProxy,
  если runtime содержит другой маршрут или выбран другой протокол.
- Добавлены агрегированные AWG_PACKET_FALLBACK_METRICS и AWG_PACKET_DROP_METRICS
  с безопасными причинами. AWG_PACKET_FLOW_PROGRESS содержит payload bytes и
  времена отправки/ожидания выходной очереди, максимум 32 изменившихся потока
  за период 10 секунд. Обычное отсутствие новых данных не считается ошибкой.
- Клик по конфигу запускает одну пробу, в том числе повторный клик по выбранному.
  Параллельные клики объединяются; при смене сервера отменённый результат
  не публикуется. Отмена во время ожидания semaphore не оставляет Running=true.
- Выбранный endpoint исключён из автоматического опроса. При запуске приложения
  выполняется одна начальная проба; остальные endpoints проверяются в фоне
  с прежними интервалами 30/120 секунд. Проверки доступности сайтов отдельные.
- AWG использует ICMP к серверу, не TCP на UDP-порту. Если ICMP недоступен,
  показано «Недоступно». React и резервный интерфейс показывают измерение;
  новый результат сразу отправляется в WebView. Подсказка уточняет смысл пинга.

## Основание

В присланных 500 строках: active=0, forwardedPackets=0, fallback=177,
packetBudgetPeakBytes=0. Прямой путь не использовался. Код консервативно выбирает
прежний стек, если имя может изменить маршрут на DIRECT/REJECT. Причины конкретных
fallback теперь агрегируются. Средняя запись в pipe около 76 мкс сама по себе
не доказывает необходимость переписывания Go на Rust.

## Проверки

- 25 целевых .NET-тестов: оба режима, совместимость старого состояния,
  неизменность сохранённых маршрутов/профиля, другие протоколы, повторные клики,
  отмена, поздний результат, фоновый опрос и ограничение параллелизма.
- 103 Rust-теста прошли; пять opt-in тестов пропущены в общем прогоне.
  Локальные Wintun и HTTP/3 запускались отдельно.
- Настоящий TCP Windows через production TUN и официальный AWG:
  по 64 МиБ с проверкой целостности для IPv4/IPv6, RTT 50 мс, фиксированные
  потери 0,5%, маленькие запросы и параллельная загрузка, замедленный читатель,
  отмена загрузки и новый запрос после паузы. Поддерживаемые тестовые TCP-потоки
  получили AWG_PACKET_ADMITTED, доменного fallback не было. Служебный multicast
  Windows вне AllowedIPs стенда учитывался отдельно как allowed_ips.
- Настоящий HTTP/3: ALPN h3, два ответа по 1 МиБ через AWG UDP/443, RTT 100 мс,
  потери 0,5%. Это локальный сервер, не YouTube.
- Wintun-стенд завершился с кодом 0 и откатом своего адаптера/двух маршрутов.
  Полное пользовательское подключение, аварийный откат и Windows 10 вживую
  в этой итерации не проверялись. Windows 10/11 пакеты собраны отдельно.
- Go-движок не менялся; его закреплённая контрольная сумма сохранена.

## Ручное сравнение

1. Запустить полный каталог нового Windows-пакета. Выбрать ior-core + TUN и
   включить экспериментальное тестирование.
2. На одном пакете сравнить `Rules` и `FullProxy`. После изменения режима
   отключить и подключить VPN; проверить AWG_ROUTING_MODE в журнале.
3. Выполнить по пять одинаковых запусков/перемоток одного видео 4K и проверок
   скорости 2×. Сохранить первый кадр, остановки, Buffer Health и Dropped Frames.
   Последний показатель может относиться к декодированию, а не к сети.
4. Теми же условиями проверить Discord и одну страницу с изображениями.
   Телефон с тем же конфигом не подключать одновременно. Сервер/DNS/MTU сохранять.
5. В FullProxy искать AWG_PACKET_ADMITTED и рост forwardedPackets/receivedPackets.
   Для unsupported family/AllowedIPs возможен диагностируемый fallback/отказ.
6. При зависании сохранить точное время и журнал в момент проблемы.
   Если улучшение не повторяется, статус остаётся «ускорение не подтверждено».

Переписывание на Rust остаётся отдельным условным этапом после сравнения и
разделения ограничений pipe, движка, маршрута, сервера и декодирования видео.
Firefox автоматически не управляется. dist.bat не запускался; dist, прежние
пакеты и локальные правки сохранены.
