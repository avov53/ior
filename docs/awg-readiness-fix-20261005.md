# Исправление проверки запуска AWG, 5 октября 2026

В пользовательском журнале запуска 18:34:27–18:34:30 подтверждены handshake,
DNS-ответы и `AWG_RAW_TCP_FIRST_DATA` для контрольного HTTPS-соединения
к `104.16.124.96:443` (flow 17). Запуск остановился с
`NATIVE_TUN_TRAFFIC_FAILED: NATIVE_TUN_HTTPS_FAILED: HTTPS_IOEXCEPTION`.

Обнаружена ошибка согласования диагностики: `HasProxiedTraffic(host)` учитывал
только `ROUTE_SELECTED` + `TUN_TCP_FIRST_REMOTE_BYTE` старого TCP-пути.
Новый пакетный путь сообщает адреса сокетов и `AWG_RAW_TCP_FIRST_DATA`,
поэтому даже успешный HTTPS-запрос не получал подтверждения PROXY.
Общий IOException скрывал конкретный код отказа внутри исключения.

Исправлено:

- Ядро явно помечает `AWG_RAW_TCP_ADMITTED` целью `PROXY`.
- Приложение связывает допуск и входящие данные по flow ID. Для проверки
  пакетного пути сравниваются фактические локальный и удалённый адреса/порты
  HTTPS-сокета. IPv4-mapped IPv6 адреса dual-mode сокета нормализуются.
- SYN/ACK, чужой поток, DIRECT/REJECT, отсутствие PROXY или отсутствие
  входящих TCP-данных не подтверждают работоспособность.
- Прежние проверки HTTPS/TLS, HTTP-ответа, DNS, маршрутов и старого TCP-пути
  сохранены. Диагностические записи ограничены по количеству.
- Безопасный код внутреннего исключения теперь доходит до результата
  проверки; адреса URL и произвольный текст исключения туда не копируются.

Проверки: 258 .NET-тестов, включая 8 новых регрессионных случаев, и 11
Rust-тестов пакетного TCP-пути прошли. Сборка Rust release также прошла.
Логи: `verification-publish/20261005-awg-readiness-fix/`.

`dist.bat` не запускался, каталоги dist и прежних пакетов не изменялись.
Новый пакет не публиковался: пользователь пересобирает dist самостоятельно.
Повторное подключение к пользовательскому серверу и работа видео в этой
итерации не проверялись. Исправление согласования доказано тестами; журнал
не содержит полного текста исходного внутреннего исключения, поэтому после
пересборки необходимо проверить, что других причин отказа нет.
