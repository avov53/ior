# AmneziaWG 3.1: пакетный путь ior-core, 8 октября 2026

Статус: экспериментальный кандидат. Ускорение YouTube/сайтов и минимальный пинг
на пользовательском сервере **не подтверждены**. Windows 10 пакет собран,
но живые сетевые проверки выполнены на Windows 11, не на Windows 10.

## Реализация

- AWG возвращён в импорт .conf, Base64-ссылок на конфиг (`awg://`,
  `amneziawg://`, `vpn://`, `wireguard://`), JSON и Clash-подписок. Это не
  обещание поддержки любого контейнера `vpn://` официального приложения.
- Сохранены числовой протокол 8 и поле состояния `AwgParameters`.
  Автоматическое удаление AWG из состояния/маршрутов отключено. Уже удалённые
  профили нужно импортировать снова; резервная копия автоматически не возвращается.
- Только ior-core + TUN Windows 10 1607+/11, за экспериментальным переключателем.
  AWG не возвращён в sing-box, Xray или самостоятельный Proxy-режим. Внутренний
  localhost-прокси остаётся для диагностики и потоков, требующих анализа имени.
- Официальный `github.com/amnezia-vpn/amneziawg-go/v3 v3.1.20260828`, Go 1.27.1.
  Модуль проверен по go.sum; лицензия включена. Движок работает отдельным
  процессом с внутренним pipeTun: системный AWG-адаптер не создаётся.
- Rust маршрутизирует и передаёт IP-пакеты TCP **и UDP**, переводит адрес/порт
  TUN в адрес профиля и обратно. Windows TCP сохраняет управление соединением.
  IPv4 и IPv6 одной семьи поддерживаются; NAT64 из прежнего эксперимента не возвращён.
- DIRECT/REJECT и правила, которым требуется TLS-имя, сохраняют прежний стек.
  Даже DNS-наблюдение не разрешает обойти возможное правило SNI. Путь закрепляется
  до первого SYN/датаграммы и не меняется в существующем соединении.
- DNS профиля имеет приоритет над общим DNS; MTU профиля сохранён. Для AWG
  резервная DNS-проба запускается через 150 мс. Булевы `on/off` преобразуются в
  эквивалентные UAPI `true/false`; исходные значения профиля сохраняются.
- Для AWG-потоков прежнего стека восстановлено ранее принятое отключение Nagle.
  ACK delay, окна и алгоритм congestion control не перенастраивались.
- Пакеты имеют framing: big-endian u32 длина, затем IP-пакет. Исправлены частичные
  записи Go. Очереди ограничены, накопление ради batching не добавлено.
- Сохраняемые raw-пакеты обоих направлений ограничены 64 МиБ на сессию;
  разрешение живёт до записи/отмены пакета. Это не лимит всей памяти процесса:
  таблицы, ограниченная сборка фрагментов и буферы Go/обычного TCP считаются отдельно.
- До 512 активных packet-потоков, до 128 сохраняемых закрывающихся TCP-потоков;
  таблицы пути ограничены 8192 записями. Half-close не закрывает чтение. При
  остановке движка очереди закрываются, TUN получает ошибку; DIRECT-подмена запрещена.
- ICMP/ICMPv6 и PMTU связываются с принадлежащим потоком; адреса, порты и
  checksum цитат восстанавливаются. Windows IPv6 глобально не меняется.

## Что уже проверено

- 101 Rust-тест: DNS, маршрутизация, checksum/ICMP, бюджет/отмена,
  обычный WireGuard, Reality/Hysteria2 и передача 64 МиБ. Пять opt-in тестов
  отмечены ignored в общем прогоне; AWG-стенды запускались отдельно.
- 327 .NET-тестов, дополнительно 27 целевых после последних правок контракта.
- Go-тесты framing, порядка, частичных чтений/записей, официального AWG,
  IPv6 endpoint; `go mod verify`. Сборка React и self-contained publish Windows 10/11.
- Прямой UDP: девять сочетаний RTT 50/100/200 мс и фиксированных потерь
  0/0,5/1%; IPv4/IPv6, UDP/443, 1/1200/4096 байт, фрагментация и освобождение бюджета.
- Настоящий HTTP/3: доверенный только стенду сертификат, ALPN h3,
  две последовательные загрузки по 1 МиБ через AWG/UDP443 с RTT 100 мс и потерями
  0,5%. Это подтверждает HTTP/3 на стенде, не выбор HTTP/3 Firefox/YouTube.
- TCP Windows через production TUN и официальный AWG: по 64 МиБ для IPv4/IPv6,
  целостность, маленькие порции, замедленный читатель и закрытие; RTT 50 мс,
  потери 0,5%. Дополнительно девять сочетаний RTT/потерь с передачей по 4 МиБ.
  Удалённый TCP-пир стенда синтетический; проценты улучшения из этих данных не выводятся.
- Остановка Go-движка завершает закреплённый packet-путь ошибкой без DIRECT.
- Штатный откат Wintun-стендов проверен. После них не обнаружены тестовые
  адаптеры, маршруты и AWG-процессы. Аварийный откат полного пользовательского
  подключения и сон/смена реальной сети в этой итерации не испытывались.

Журналы/JSON и контрольные суммы: `verification-publish/20261008-awg-packet-stage1`.
Результаты стенда являются проверкой корректности, не сравнением скорости
пользовательского YouTube. Сервер, ключи и обфускация не перенастраивались.
`dist.bat` не запускался. Старые пакеты и dist сохранены.

## Ручное сравнение

1. Полностью закрыть другой ior и отключить VPN телефона с тем же конфигом.
2. Кандидат: `verification-publish/20261008-awg-packet-stage1/windows-11/ior.exe`
   (на Windows 10 — соседняя `windows-10`). Запускать из полной папки пакета.
3. Включить экспериментальное тестирование, выбрать ior-core и TUN,
   повторно импортировать оригинальный конфиг или обновить подписку.
4. Контроль: сохранённый `20261005-awg-final-stage7/windows-11`. Для сравнения
   использовать `start-control.cmd` рядом с кандидатом: он задаёт отдельный
   `IOR_APPDATA_DIR`, чтобы старая версия не пересохранила текущее состояние.
   В контроль импортировать тот же .conf и вручную выставить тот же маршрут/DNS.
5. Чередовать пять повторов контроля/кандидата: одна страница с изображениями,
   Telegram Web, одно видео YouTube с одинаковым 4K и кодеком, одинаковая
   перемотка, скорость 2×. Разделять первый и повторный заход. Записывать первый
   кадр, остановки, Buffer Health и Dropped Frames; последний показатель может
   отражать декодирование, а не сеть. Пинг — к одному адресу одним методом.
6. В журнале `AWG_PACKET_ADMITTED` подтверждает прямой путь конкретного потока.
   `AWG_PACKET_FALLBACK` объясняет использование прежнего стека. Доменные
   DIRECT/REJECT-правила могут закрыть прямой путь; настройки маршрута не обходятся
   автоматически ради результата. `AWG_PACKET_METRICS`, `AWG_RAW_PACKET_METRICS`
   и `AWG_PIPE_METRICS` показывают потери, бюджет, ожидание очереди и стоимость pipe.
7. Если проблема сохраняется, сохранить точное время и журнал во время зависания.
   При неоднозначном сравнении статус остаётся «ускорение не подтверждено».
   Firefox автоматически не управляется.

## Условный этап Rust

Полного переписывания в этом кандидате нет. Оно начинается после пользовательского
сравнения и анализа ограничивающего участка. Сначала отделяется цена pipe от
движка/маршрута/сервера. Затем — отдельный модуль Rust на основе аудита
WireGuard/BoringTun и AWG 3.1, с перекрёстными тестами против закреплённого Go-эталона:
handshake, обфускация, header protection, padding, cookies, rekey, replay protection,
TCP/UDP и тот же стенд. Переход языка сам по себе ускорение не доказывает.
