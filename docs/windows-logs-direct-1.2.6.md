# Windows 10/11 — тестовая 1.2.6: журнал и DIRECT IPv4

В журнале Windows 11 оба ядра не падали: готовность VPN была подтверждена.
Повторные таймауты локального назначения уже относились к DIRECT. Маршрут этого
назначения не меняется, системные службы не отключаются.

## Журнал

INFO — подтверждённые служебные события и успешный IPv4-резерв.
Предупреждение — отдельный неуспешный поток при уже подключённом VPN.
Ошибка — отказ запуска/готовности, неожиданное завершение, сетевая петля,
ошибка восстановления. Произвольный HTTP EOF не объявляется подтверждённой
служебной проверкой и остаётся предупреждением; общая маска скрытия EOF не используется.

Уровень фиксируется при получении строки и одинаково используется интерфейсом
и фильтром копирования. Аннотация не удаляет исходный текст и flow ID. Группировка
предупреждений по коду/причине/назначению в пределах 60 секунд выполняется только
при отображении. Видны число повторов и первое/последнее время. «Копировать всё»
сохраняет все имеющиеся исходные строки, а структурированная диагностика ядра
сохраняется по действующей политике. Критические ошибки не группируются.

## Windows 10

Только Windows 10-хост включает необязательный флаг `network.directIpv4Fallback`.
При DIRECT, отсутствии физического IPv6 и подтверждении имени актуальным DNS-
наблюдением исходного IPv6-адреса ядро может разрешить имя в IPv4 и подключиться
напрямую. Выбор правила происходит по исходному назначению; порт и DIRECT
сохраняются. SNI без DNS-подтверждения, числовой IPv6, PROXY/REJECT, наличие
физического IPv6 и выключенный флаг не включают резерв.
Сохраняются существующие физическая привязка, защита от петель и внешний
15-секундный бюджет подключения с отменой. Глобальные настройки IPv6 не меняются.

## DNS и Windows 11

В текущих сохранённых локальных настройках указан один DNS: 1.1.1.1.
Исторический журнал также показывает попытки к нему, но не содержит полного
снимка настроек на момент двух таймаутов. Новый запуск записывает источник,
число и фактический список резолверов. Новые публичные DNS автоматически не добавляются.

Проверки подтвердили существующий резерв при медленном первом резолвере,
ошибку при полном отказе и отсутствие неявного второго DNS при единственном
настроенном сервере. DNS-алгоритм, MTU, буферы и таймауты Windows 11 не менялись.

Локальное сравнение старого и нового бинарника: три запуска и три передачи
4 МиБ по loopback каждого варианта. Все данные совпали. Медиана старта была
35,1/31,4 мс, локального тестового сценария передачи — 23,0/47,3 мс (старое/новое).
Значения имеют заметный разброс и включают работу тестового сценария; это не
измерение реального VPN. Отсутствие ухудшения нового бинарника не подтверждено.
Поэтому Windows 11-пакет сохраняет прежний проверенный бинарник ядра,
а новый бинарник с DIRECT-резервом включён только в тестовый Windows 10-пакет.
Для Windows 11 изменён журнал; ускорение не заявляется.

## Проверки и передача

438 тестов .NET пройдено; 154 Rust-теста пройдено, 12 opt-in пропущены.
Отдельно выполнено локальное старое/новое сравнение процессов и передачи.
Rust-тест DIRECT использует локальный DNS и TCP, проверяет успешное соединение
без обращения к прокси. Проверены условия запрета резерва и исходные DNS-сценарии.
DOM/bridge проверен с имитированным хостом. Тест группировки проверяет окно
60 секунд, разделение назначений и отсутствие группировки ошибок.

Распаковать полный ZIP в новую папку и закрыть прежнюю копию ior.
На настоящем Windows 10 проверить оба ядра, Discord, сайты и видео, переключение
протоколов и возвращение AG DNS. На Windows 11 проверить прежнюю скорость и
новые уровни журнала. Автоматические тесты не подтверждают эти реальные сценарии.

Android и GitHub не менялись. Прежние пакеты и dist сохранены.
