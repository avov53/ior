# Roblox: DNS-сбой до выбора маршрута

В новом журнале 19:46 запросы A/AAAA (flows 419, 420, 422) завершаются NotFound
между DNS_QUERY_PARSED и ROUTE_SELECTED. Из локального отчёта: проверялся AWG;
следующий запуск 19:46:58 — Hysteria2. Предыдущая правка именованного TCP не могла
исправить запрос, которому DNS вообще не дал адреса.

## Подтверждённый дефект и исправление

TunDns вызывал обычный router.decide(name, None). Если перед доменными/MATCH
правилами находилось IP/GeoIP-правило с разрешением имени, маршрутизатор сначала
делал A-запрос через физический bootstrap-DNS. Его пустой ответ давал NotFound;
запрос до профильного DNS через PROXY уже не доходил. Это круговая зависимость:
имя требуется разрешить ещё до выбора маршрута самого разрешения.

Добавлен отдельный выбор DNS-маршрута по доменным правилам и завершающему MATCH,
без предварительного bootstrap-запроса. IP-CIDR/IP-SET на стадии DNS отложены:
адрес назначения ещё неизвестен. При открытии TCP/UDP или пакетного потока
исходный порядок всех правил и IP-REJECT/DIRECT проверяется по полученному адресу.
Доменные DIRECT/REJECT работают до запроса DNS. DNS-ответы/подсказки, TTL, MTU,
серверы resolver, криптография, сервер и передача AWG не менялись. Доменные DNS-
правила сохранены; при одном IP-DIRECT без доменного правила DNS идёт по финальному
маршруту, а само соединение может идти DIRECT по IP. Это явное разделение DNS
и маршрутизации данных, не скрытый DIRECT и не переписывание выбранного профиля.

Правка общая для всех протоколов ior-core в TUN. Сохранена предыдущая отправка
подтверждённого имени для потокового PROXY; AWG/WireGuard сохраняют пакетный путь.
Обязательных полей состояния и нового переключателя нет.

## Проверки

Локальная фикстура воспроизводит прежний NotFound: bootstrap возвращает NOERROR
без A-записей, первый IP-SET требует разрешения. Старый router.decide завершается
NotFound. Исправленный TunDns получает корректный A-ответ через контролируемый
PROXY без второго обращения к bootstrap. После DNS тот же IP по IP-REJECT остаётся
REJECT. Отдельно проверены доменные DIRECT/REJECT и MATCH.

11 тестов native_router, 13 DNS TUN, 16 AWG и 2 TUN прошли; группы пересекаются.
Release Rust и self-contained Windows 10/11 publish прошли. Системные маршруты
и пользовательский сервер проверками не менялись; тестовый DNS только loopback.
Ошибки первой тестовой фикстуры (NXDOMAIN вместо нужного пустого ответа) устранены;
финальная фикстура воспроизводит именно наблюдаемый NotFound.

## Пользовательская проверка

Закрыть прежний ior, запустить полный новый пакет Windows 11/10 из awg-current,
переподключить VPN, обновить Roblox. Проверить превью и изображения в плейсе на
AWG, Hysteria2 и VLESS Reality. Если не загрузятся, включить ресурсный launcher
и записать журнал сразу после сбоя. В новой сборке DNS-запросы при IP-правилах
должны получать ROUTE_SELECTED и доходить до DNS resolver; NotFound до маршрута
по этой причине устранён. Вход в игру и все приватные картинки ещё не подтверждены.

Статус: воспроизводимый общий DNS-дефект исправлен; полное восстановление Roblox
требует проверки в браузере/игре. Windows 10 вживую не проверена. Быстрые контрольные
архивы AWG сохранены и проверены по хешам, dist и APPDATA не заменялись.
Промежуточные файлы и кеши этой работы очищены. Firefox не автоматизировался.
