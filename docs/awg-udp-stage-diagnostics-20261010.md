# AWG UDP: диагностический кандидат стадий передачи

10 октября 2026. Базовый запуск e8ad8f78e3b549e2876962982f2df0f4, ядро 5675a955181e. Его ограниченный отчёт 71931 байт сохранён как udp-control-resources.jsonl, пакет — udp-diagnostic-control-overlay.zip. Кандидат 3be6808c6cb4. Текущее VPN и dist не изменены; прежние быстрые/Roblox-контроли сохранены.

Анализ: крупные прямые UDP-потоки 448 (163955358 байт), 313 (64825573), 475 (27689859) не были представлены как однозначные googlevideo-потоки в resources.jsonl. Существовавшая диагностика выбирала имя только при единственной DNS-записи. Общий приём продолжался, потери очереди/бюджета в присланном интервале не зарегистрированы. TCP-поток 326 имел 2508836 байт и длительную паузу, но его нельзя без данных браузера объявить зависшим видеосегментом. UDP не является самостоятельным доказательством HTTP/3.

Изменения исключительно диагностические:
- Возможные DNS-имена: не более четырёх подходящих селектору, с общим числом имён и отметкой dns_candidates. Они не считаются точным именем запроса и не меняют маршрут.
- Видео-предустановка дополнительно показывает безымянные прямые UDP/443 потоки после 1 МиБ приёма как unknown_bulk_candidate. Известные имена вне селектора исключаются; неизвестный поток не маркируется YouTube автоматически. Payload, URI и QUIC/TLS содержимое не записываются.
- RESOURCE_NATIVE_DELIVERY: receivedBytes — целые расшифрованные IP-пакеты, сопоставленные потоку; sentBytes — передано в его канал; rxQueuedBytes — оценка ожидания; droppedPackets и receiveWaitUs; readEof здесь означает закрытую стадию ingress. Счётчики включаются только при явно активной диагностике и поддерживают Rust/Go.
- RESOURCE_PACKET_PROGRESS: receivedBytes — L4 payload, полученный Manager, tunDeliveredBytes — L4 payload после успешной записи в Wintun, maxPacketBytes — максимальная длина целого IP-пакета. Стадии имеют разные единицы: IP-байты ingress не сравниваются побайтно с L4 payload. Wintun accepted не означает, что браузер потребил данные.
- Паузы крупных живых потоков имеют редкий heartbeat, даже если байты не меняются. durationMs — первое транспортное сообщение от открытия соединения, не HTTP first byte и не первый кадр.
- Без изменения обработки пакетов записываются ICMP type/code и PMTU, если они действительно получены. MTU автоматически не меняется.
- resources.jsonl остаётся не более 256 КиБ; при заполнении сохраняются начальные 32 КиБ и последние 128 КиБ целыми JSON-строками, отмечается RESOURCE_REPORT_COMPACTED. Новый запуск имеет отдельное содержимое. При обычном запуске дополнительный захват выключен.

Проверки: Rust packet routing/ledger 7, ingress/бюджеты/отмена 7, resource filter/candidates 2, routing 13, DNS 15, fragments 3 (группы пересекаются). Тесты проверяют обратную IPv4/IPv6 привязку, разделение ожидания и доставки, кандидатов без URL/ложных суффиксов, сохранение DIRECT/REJECT. .NET 10: безопасный запуск, разрешённые поля, текущий run, компактный отчёт с началом/хвостом и валидными JSON-строками. Последовательный локальный HTTP/3 Rust и Go против официального Go тестового сервера: ALPN h3, по два ответа 1 МиБ с проверкой содержимого, RTT 100 мс, потери 0,5%. Прогоны успешны; это совместимость локального стенда, не сравнение YouTube на пользовательском сервере. Release и Windows 10/11 publish прошли. Тест живого Wintun и Windows 10 в этой работе не выполнялся; ledger проверен на валидных IPv4/IPv6 пакетах.

Параметры сервера/профиля, DNS Roblox, окно 2 МиБ, шифрование, маршруты, rekey и рабочие соединения не менялись. Новой оптимизации скорости нет. Причина остановки конкретного HTTP-запроса ещё не установлена.

Ручная проверка: закрыть прежний ior, запустить Start-VideoDiagnostics.cmd (по умолчанию Windows 11; аргумент windows-10 для Windows 10), выбрать AWG Rust. В журнале должна быть сборка 3be6808c6cb4. Для одного зависшего videoplayback нужны время по Москве, h3/h2, удалённый IP и тайминги без ссылки/cookies. Затем один последовательный Go-контроль на том же профиле, сервере, DNS, маршрутизации и видео; телефон с тем же конфигом одновременно не использовать. Если Firefox подтверждает h3, один временный ручной h2-контроль с последующим восстановлением HTTP/3; настройка автоматически не меняется.

Классификация результата: ingress растёт, Manager/TUN нет — искать локальную стадию; Manager растёт, Wintun нет — проверять запись; все стадии доставляют, а видео останавливается — анализ браузерного запроса/аудио-видео; decoded ingress прекращается — это ещё не доказательство отказа CDN, возможны внешние потери либо приём/декодирование движка, требуется Go/Rust контроль. Диагностические накладные расходы учитывать при сравнении. Проблему считать устранённой только после повторяемого отсутствия зависаний на 1x/перемотке/2x и сохранения Roblox.

Готовые пакеты, этот отчёт, скрипты, контроль и один отчёт сбоя сохраняются. Подробные журналы успешных проверок и проверенные промежуточные build caches очищаются.
