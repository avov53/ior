# CDN DNS: отрицательный CNAME + SOA и резервный resolver

9 октября 2026. Исправляется недостающий случай предыдущего кандидата 2930f2da91db: код исключал ответы с SOA из проверки резервного DNS. Новый кандидат f3fc200426e3.

Реальные SOCKS UDP-пробы через текущее Hysteria2: 77.88.8.8 вернул tr.rbxcdn.com → trns1.rbxcdn.com с SOA и без A/AAAA; сам trns1 также вернул NOERROR/NODATA + SOA. 8.8.8.8 вернул полную цепочку CNAME с A и AAAA. Для HTTPS (65) сохранены исходные сервисные/отрицательные ответы, без переписывания hints. Действующая DNS-служба TUN старого Hysteria2 c705a09c648c вернула SERVFAIL. Работающее соединение не отключалось. Эти пробы выполнены через Hysteria2, не через AWG.

Общий DNS-код TUN теперь проверяет резервные настроенные resolver для A/AAAA NOERROR без адресов, включая CNAME + SOA. При положительном резерве клиент получает неизменённый ответ резерва. Если резерв недоступен или также не имеет адресов, возвращается исходный корректный ответ побайтно, а не синтетический успех или SERVFAIL. NXDOMAIN, один resolver, маршруты DIRECT/REJECT, IPv4-only ограничения и HTTPS/SVCB сохраняют прежнюю обработку. Кеш не закрепляет отрицательный ответ первого resolver при наличии других: уже закешированный положительный ответ резерва используется сразу. Диагностический код TUN_DNS_ADDRESS_NODATA безопасно отличает этот случай.

Локальная регрессия: CNAME, CNAME+SOA, SOA/NODATA и NXDOMAIN; A/AAAA, положительный резерв, отказ резерва, отрицательные ответы обоих resolver, повторные запросы/кеш и сохранение исходного ответа. Прошли tun_dns 15, native_router 12, dns_exchange 4, AWG 16, tun 2; группы пересекаются. Дополнительный opt-in тест непосредственно вызывает новый TunDns на реальных DNS/TCP-ответах через существующий локальный proxy: основной требует резерва, A успешно получается от резерва и повторно из кеша. Настоящий отрицательный AAAA остаётся допустимым. Тест не создаёт VPN-сессию, адаптер или маршруты. 7 расширенных AWG-стендов не повторялись.

Rust release и Windows 10/11 publish успешны. AWG-движок, MTU, DNS профиля, TCP-окна, keys и обфускация не изменены. Контрольные архивы stable-fast-control.zip и seek-fast-control-overlay.zip сохранены; dist не затронут.

Статус: воспроизведён и исправлен выбор DNS-ответа при CNAME+SOA. Загрузка конкретного WebP по штатному DNS через новый AWG TUN, отображение превью/аватаров в Firefox и Roblox Player ещё не подтверждены. Windows 10 живая проверка и отдельная Reality-регрессия не выполнялись. Кандидат выдаётся для этой проверки, без заявления полного исправления Roblox.

Запуск: закрыть прежнее приложение, открыть verification-publish/awg-current/windows-11/ior.exe (или windows-10), подключить AWG. Для ограниченных диагностических событий Roblox вместо прямого запуска можно использовать Start-RobloxDiagnostics.cmd. Проверить в отчёте запуска сборку f3fc200426e3, повторно открыть Firefox и игру. Если ошибка осталась, нужен HTTP/Network результат конкретного ресурса и DNS-события этого запуска.
