# Roblox: диагностический кандидат без настройки скорости AWG

Пользователь наблюдает отсутствие превью плейсов на сайте и изображений внутри
игры на ior-core + TUN с разными протоколами. В app.txt 500 строк, но нет имён
Roblox/rbxcdn и ошибок TCP. DNS-отказы относятся к другим доменам. Контроль
Xray/sing-box и ошибка конкретного HTTP-запроса пользователем пока не предоставлены.
Поэтому причина отсутствия изображений и исправление Roblox НЕ подтверждены.

## Выполнено

- Добавлена временная метадата-диагностика, выключенная по умолчанию. Core читает
  IOR_RESOURCE_DIAGNOSTICS — до восьми доменов/суффиксов через запятую. Фильтр
  проверяет границы домена, не принимает URL, IP, токены или пути. У запуска
  Roblox начальные фильтры roblox.com/rbxcdn.com; это не перечень всех возможных CDN.
- RESOURCE_DNS_QUERY/RESPONSE показывает тип, маршрут, RCODE, число ответов и TC;
  RESOURCE_ROUTE/PACKET_ROUTE — выбранный маршрут/пакетный путь; RESOURCE_TCP_FIRST_BYTE,
  ERROR/SUMMARY — первый байт, сторона ошибки, общий объём и закрытие. Нет анализа
  содержимого TLS/HTTP, cookies, URL запросов или изображений. HTTP-статус нужно
  посмотреть вручную в Network браузера. Пер-пакетных подробных событий нет.
- Исправлена подтверждённая классификация журналирования: DNS NODATA/NXDOMAIN,
  отказ resolver, усечение и несовпадение ответа не называются общим транспортным
  отказом. Решения по ответам/повтору и сами пакеты остаются прежними; успешного
  пустого ответа вместо ошибки нет. Это не доказательство исправления картинок.
- Добавлены безопасные поля RCODE/answerCount/TC в C# журнал и экспорт.
- Новый обязательный параметр состояния/контракта не добавлен. Маршруты и
  DIRECT/REJECT, MTU, DNS профиля, обфускация, Rust и буфер 512 КиБ не менялись.
  Дополнительных оптимизаций AWG нет: исходный журнал не показывает ограничения.

## Проверки

3 ресурсных Rust-теста, 3 DNS engine, 12 DNS TUN, 2 диагностики, 16 AWG,
1 локальная WireGuard TCP/UDP-проверка и 2 .NET-проверки экспорта прошли.
Группы пересекаются; числа не складываются в уникальный набор. Проверены
выключенный фильтр, ложные суффиксы/URL, отрицательные ответы без переписывания,
параметры DNS и целостность локальной передачи. Release Rust и Windows 10/11
publish прошли. Живой Roblox, ускорение/регрессия YouTube и Windows 10 не проверены.
Статус: диагностический кандидат, исправление Roblox не подтверждено.

## Что проверить

1. Полностью закрыть ior. На Windows 11 запустить Start-RobloxDiagnostics.cmd
   из awg-current. Для Windows 10 вызвать его с аргументом windows-10.
   PowerShell-альтернатива Start-RobloxDiagnostics.ps1 принимает Package и Domains.
2. В приложении выбрать ior-core + TUN и тот же профиль/маршрут; открыть Roblox,
   воспроизвести отсутствие превью и ресурсов внутри одной игры. Указать точное
   время и сохранить журнал сразу после сбоя. Если RESOURCE-событий нет, нужны
   домены фактических запросов; зашифрованный DNS/ECH могут скрывать имя от ядра.
3. В Network браузера вручную найти один failed-запрос: достаточно домена и
   HTTP-статуса/текста ошибки. Cookies, подписанные query-параметры и токены не присылать.
4. Сравнить Xray/sing-box в TUN с теми же сетью/сервером/маршрутом. После этого
   локализовать дефект общего TUN/DNS или внешние правила/ответы CDN. Не обходить
   REJECT и не включать скрытый DIRECT. Исправлять только подтверждённый этап.

Обычный запуск ior.exe не включает диагностику (если пользователь явно не задал
IOR_RESOURCE_DIAGNOSTICS в окружении). Скрипты задают её только дочернему процессу,
не меняют глобальные переменные и не останавливают уже работающий VPN.
Firefox не автоматизировался.

Оба быстрых контроля сохранены: stable-fast-control.zip — полный базовый пакет,
seek-fast-control-overlay.zip — последний улучшенный вариант поверх него.
APPDATA/профили не заменяются. При ухудшении использовать контроль по инструкции
awg-accepted-rollback-20261009.md. Промежуточные файлы и кеши кандидата очищены;
пакеты, скрипты, отчёт и контрольные суммы остаются в одном awg-current.
