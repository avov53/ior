# Reality/Vision: чтение без лишнего копирования

Кандидат: `verification-publish/20261005-reality-throughput-stage3/windows-11/ior.exe`.
Контроль: `verification-publish/20261005-reality-stable-stage2/windows-11/ior.exe`.

В этой итерации изменён только `vision_io.rs`. После проверки VLESS-ответа и завершения Vision-обрамления чтение идёт непосредственно в буфер получателя через прежний TLS либо raw-reader. До этой границы декодер обязателен. Накопленный остаток отдаётся перед последующим чтением сокета; вместо побайтного извлечения из VecDeque используются копирования двух непрерывных участков.

Размер выдаваемой порции сохраняется до 16 КиБ: память ограниченных очередей не увеличивается. TLS-проверка сертификата, криптография, MTU, DNS, параметры сервера, маршрутизация, TCP-окна, Nagle, таймеры моста, flush и half-close остаются прежними. UDP/443 остаётся отдельной ранее добавленной настройкой, выключенной по умолчанию. `dist.bat` не запускался; прежние пакеты сохранены.

## Проверки и измерение

- Rust: 93 теста ядра прошли, отдельный замер первоначально ignored. После последнего изменения ограничения порции повторно прошли все пять тестов vision_io в Release, включая замер.
- Проверены фрагментированный заголовок/граница Vision, остаток перед raw-потоком, EOF, команда END без включения raw, неверная идентичность/команда, циклический буфер. В общем прогоне присутствуют предыдущие проверки flush, half-close и четырёх параллельных передач по 64 МиБ.
- Финальный пакет однократно подтвердил HTTPS, UDP/DNS и WebSocket Hello Discord через текущий Reality-профиль. Проверка работает в Proxy-режиме без изменения сети Windows; она не заменяет проверку TUN-видео и голосового канала.
- Self-contained win-x64 пакет собран. .NET и интерфейс не изменялись; их полные наборы проверок повторно не запускались ради экономии времени и лимитов.

Локальный TCP-loopback замер: три чередующихся повторения по 64 МиБ на каждый вариант, побайтовая проверка содержимого. Контроль повторяет прежнюю выдачу по 16 КиБ через промежуточную очередь; кандидат использует новое чтение с тем же ограничением порции. Измеряется только получение raw-данных после границы Vision, без TLS-handshake, браузера и внешней сети.

| Чтение 64 МиБ | Три результата | Медиана |
|---|---|---|
| Прежнее | 117383 / 118516 / 122253 мкс | 118516 мкс |
| Новое, порция ≤16 КиБ | 44451 / 46545 / 57565 мкс | 46545 мкс |

Медиана локального участка сократилась на 60,7%. Это уменьшение накладных расходов чтения, а не обещание роста скорости YouTube на 60,7%. Первый предварительный вариант с большей порцией не выдаётся: финальный кандидат сохраняет прежний размер порции.

## Статус и ручная проверка

Подтверждено ускорение локального участка чтения и отсутствие ошибок в перечисленных проверках. Ускорение сайтов, 4K и приложений, а также отсутствие сетевых регрессий пока **не подтверждены**. Стенд RTT 50/100/200 мс с потерями 0/0,5/1% и p95 маленьких запросов под нагрузкой в этой итерации не выполнен; критерии всего плана не объявляются пройденными. Экспериментальное HTTP/3 не включено в сравнение. Кандидат выдаётся отдельно от контроля.

Сначала сравнить контроль и кандидат с одинаковыми настройками, по пять повторов одного видео 4K: первый кадр, перемотка, 2×, число остановок и запас буфера. Отдельно — одинаковые страницы и запуск Discord. Первый и повторный заход фиксировать раздельно. Если остановок больше или повторяемого улучшения нет, использовать сохранённый контроль; дополнительные изменения одновременно не включать.

Логи тестов и контрольные суммы находятся рядом с пакетом. Автоматизация Firefox не использовалась.
