# Windows 10 — тестовая 1.2.6 с временным отключением AG DNS

Изменения включаются только на Windows 10 (14393–21999) и только для TUN
ior-core/Xray. Proxy и Windows 11 не приостанавливают правила AG. Процессы
AG Unlocker и его файлы не удаляются, неизвестные/корпоративные правила не изменяются.

Перед запуском ior сохраняет подтверждённые локальные правила AG для двух
известных доменов Cloud Code и временно удаляет их. Правила распознаются по
метаданным, поэтому работающий процесс AG не требуется. Если оставшаяся
DNS-политика мешает VPN, запуск не продолжается и удалённые правила возвращаются.
Если правила отличаются от поддерживаемой простой конфигурации, они не удаляются.

Файлы в `%APPDATA%\ior`:
- `ag-dns-backup-*.json` — отдельные резервные копии исходных правил;
- `ag-dns-recovery.json` — активный журнал восстановления (не удалять вручную);
- `dns-policy-report.json` — подробности DNS-конфликта;
- `win10-tun-failure.json` — диагностика адаптера/PnP при неудаче Xray.

После отключения VPN, отмены или неудачного запуска правила восстанавливаются.
При управляемом переключении серверов/ядер используется текущая приостановка.
Если приложение аварийно закрыто, восстановление выполняется при следующем
запуске ior, когда прежнее ядро уже не работает. Если ядро ещё активно,
сохраняется текущая приостановка до остановки соединения.

Изменившиеся или заново созданные сторонней программой правила не перезаписываются.
В случае конфликта журнал остаётся на диске, дальнейший запуск блокируется
до восстановления. Если AG вернул правила во время VPN, показывается запись
предупреждения в журнале; повторного удаления в цикле нет. Связанные функции AG
могут не работать, пока VPN использует временное отключение.

Для Xray Windows 10 ожидание собственного адаптера увеличено до 30 секунд.
После этого выделяется отдельный прежний бюджет проверки HTTPS/UDP. При завершении
ядра ожидание адаптера прекращается раньше. Сертификаты, проверки готовности
и физического маршрута остаются прежними.

## Проверка сотрудником

1. Закрыть старый ior, распаковать полный новый ZIP в отдельную папку.
2. Запустить ior с обычным запросом администратора. Проверить ior-core TUN
   с Hysteria2 и VLESS Reality, затем Xray TUN.
3. Проверить уведомление о приостановке AG, затем отключить VPN и проверить
   запись о восстановлении. Не удалять резервные копии/журнал.
4. Проверить переключение сервера/ядра, отмену запуска и повторное подключение.
5. При сбое передать журнал и нужный локальный отчёт после просмотра его содержимого.
   Не передавать `state.json`, конфиги, ключи или ссылки подписок. DNS-отчёты могут
   содержать внутренние имена организации; это локальные файлы, они не отправляются автоматически.

## Локальная проверка

413 тестов .NET прошли. Новые проверки покрывают отсутствие AG, частичное удаление,
ошибку сохранения, восстановление из журнала после сбоя, повторное использование
активной приостановки, конфликты с изменёнными/чужими правилами, повторное создание
правил, раннее завершение ядра и непринятие чужого адаптера. Проверены синтаксис
PowerShell без выполнения изменений сети и нормализация Windows 10 CIM-адресов.
DOM/bridge интерфейса прошёл проверку с имитированным хостом.

Настоящие DNS-правила и маршруты локального компьютера при тестах не изменялись.
Запуск VPN, восстановление NRPT и создание адаптера на проблемной Windows 10
требуют проверки сотрудником; исправление не объявляется подтверждённым до неё.
Новый Xray не включался. Android, dist, старые сборки и релизы GitHub сохранены.
