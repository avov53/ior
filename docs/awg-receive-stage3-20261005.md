# AWG: сверка конфигурации и приёмное окно, 2026-10-05

Статус: исправление и пакет готовы; **ускорение сайтов и YouTube 4K пока не подтверждено**. Реальный браузер и TUN в этой итерации автоматически не запускались. Все проценты ниже относятся только к локальному стенду.

## Что установлено

- `test1.conf` и сохранённый AWG-профиль совпадают по endpoint, ключам, локальному адресу, AllowedIPs, MTU, DNS и всем 20 AWG-параметрам. HeaderProtectionKey в экспорте Base64, в состоянии hex; байты совпадают. Ключи и endpoint в отчётах не сохранены.
- Локальный адрес только IPv4; MTU 1280; DNS 77.88.8.8 и 8.8.8.8; DNS override отсутствует. AllowedIPs `::/0` не создаёт локальный IPv6.
- Код ior декодирует его WireGuard/AWG-ссылки в текст конфигурации и использует тот же парсер, что для `.conf`. Четыре новых теста проверяют эквивалентность трёх схем ссылок, все параметры, нормализацию ключа/boolean и получение обычного AWG-конфига через HTTP-подписку. Менять формат подписки ради скорости оснований нет.
- Официальный формат Amnezia `vpn://` также может содержать Base64URL + Qt-compressed JSON. Это другой контейнер импорта; универсальная поддержка всех экспортов Amnezia не заявляется и в этот пакет не добавлялась.
- В `app.txt` 503 строки, 500 событий, фрагмент 23:55:21–23:56:33. 23 наблюдения первого TCP-ответа: медиана 122 мс, p95 198 мс, максимум 505 мс. Есть 24 DNS_IPV6_NODATA и IPv6 UDP-попытки без известного имени, но в фрагменте нет событий ошибок потоков или сброса очередей. Это частичный журнал; исходов всех UDP-попыток и скорости активного видео он не устанавливает. IO_WAIT и idle-close не считаются доказательством поломки транспорта.

- [Android GoBackend](https://github.com/amnezia-vpn/amnezia-client/blob/3e9b70a5f1dd939b0df062881ac404536c678846/client/android/wireguard/src/main/kotlin/org/amnezia/awg/GoBackend.kt) передаёт TUN fd и настройки в Go. ior дополнительно завершает TCP локальным TUN-netstack и создаёт исходящий TCP smoltcp. Код официального клиента не переносился. Шифрование уже выполняет официальный AWG-компонент. Прямая передача исходных IP-пакетов, переделка pipe и переключение Windows backend не включены: проверено ограничение приёмного окна, поэтому сначала принимается эта отдельная оптимизация.

## Изменения

- Закреплена локальная копия smoltcp 0.12.0 с лицензией 0BSD; Cargo registry не редактировался. Исправлен `last_scaled_window`: исчерпанная правая граница ранее объявленного окна даёт ноль, а не отрицательное вычитание последовательностей с паникой. Сравнение учитывает wraparound. Исправление общее для обоих TCP-участков; тест проверяет обычные и переходящие через границу sequence numbers.
- Только исходящие TCP-сокеты AWG по умолчанию получают RX 512 КиБ, TX остаётся 128 КиБ. Дополнительные 384 КиБ на сокет ограничены общим бюджетом 64 МиБ на сессию. При его исчерпании новый сокет получает RX 128 КиБ. Разрешение освобождается при закрытии/отмене.
- Nagle остаётся выключенным на исходящем AWG; ACK delay и алгоритм None сохранены. Настройки локального TUN-netstack и других протоколов не менялись. CUBIC остаётся выключенным.
- В UDP-диагностике добавлен фактический адрес транспорта и один первый ответ на поток, включая нулевой datagram без повторного журналирования. Отказ несовместимого семейства остаётся до создания relay; DIRECT и DNS-ответы не переписываются.
- MTU, DNS, ключи, обфускация, Go-адаптер, сервер и запуск TUN не изменялись. Публичный IPC и состояние совместимы, новых настроек нет.

## Измерения и проверки

Официальные AWG-адаптеры, синтетические ключи, IPv6 loopback endpoint, фиксированная задержка, без системных маршрутов. Три чередующихся повтора RX 128/512 КиБ, RTT 100 мс, потери 0%, загрузка 64 МиБ с проверкой каждого байта:

| Метрика | RX 128 КиБ | RX 512 КиБ |
|---|---:|---:|
| Медиана загрузки | 61 421,414 мс | 15 958,848 мс |
| p95 небольших запросов | 128,118 мс | 132,564 мс |
| p95 запросов под нагрузкой | 133,003 мс | 131,240 мс |

Сокращение времени 74,017%; рост p95 3,47%. Критерии ≥15% и ≤5% выполнены. Замедленный читатель, параллельные передачи и half-close завершились без прежнего падения. Дополнительно шесть коротких сценариев по 1 МиБ: RTT 50/200 мс × потери 0/0,5/1%, включая upload/download, параллельные передачи и замедленного читателя. Это проверки поведения, а не полный 64 МиБ performance matrix и не измерение YouTube.

- 382 теста smoltcp с IP/TCP/UDP features — прошли.
- 86 Rust-тестов workspace, включая включённый официальный AWG TCP/UDP/DNS/reconnect — прошли. Два opt-in стенда не входят в эту сумму; receive gate и smoke запускались отдельно.
- 249 .NET-тестов — прошли. Отдельно включённый тест приватного управления новым бинарником и освобождения listener — прошёл. Обычный набор не означает запуск всех opt-in пользовательских сетевых испытаний.
- TypeScript/Vite/standalone UI, release core и self-contained Windows x64 publish — прошли.
- Go-исходники и адаптер не изменены; повторный Go test не выполнен, go.exe недоступен в текущем окружении. SHA-256 официального адаптера повторно проверен: `7418c25915f59050d97f669d6cfbc81ec2cd220ba02ac08e0ff0f84f43f88bd7`.
