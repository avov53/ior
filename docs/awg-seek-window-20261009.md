# AWG: окно fallback TCP и ограниченная диагностика перемотки

9 октября 2026. Контроль пользователя 0d982215ea46 сохранён в seek-buffer-control-overlay.zip. Предыдущие быстрые и Roblox-контроли сохранены. Кандидат: 9a8886c5909e, Windows 10/11 в одном awg-current. dist и действующий VPN не изменены.

Firefox network.trr.mode=2 указывает предпочтительный DoH: зашифрованные DNS-ответы могут не попадать в наблюдения TUN, поэтому имя становится известно после установления TCP. Это объясняет возможность fallback, но не доказывает путь конкретного видеосегмента. Конфигурация браузера не менялась, маршруты и текущие TCP-сеансы не переключались.

На скриншотах videoplayback HTTP 200, загрузки примерно 40–61 МБ за 18–29 с. Это ориентировочно 15–18 Мбит/с по полному времени запроса, включая ожидание, не чистая транспортная скорость. NS_BINDING_ABORTED при перемотке может быть отменой плеером. Полные signed URL, cookies и параметры запросов не сохранены.

Измеренный локальный fallback TCP gate: Rust AWG против официального Go тестового сервера, синтетические ключи, RTT 200 мс, фиксированные потери 0,5%, три чередующиеся пары, 8 МиБ параллельно 20 небольшим запросам. 512 КиБ: времена 9,724641 / 11,122719 / 7,181424 с; 2 МиБ: 2,932176 / 2,335324 / 2,265518 с. Медиана 9,72 → 2,34 с (около 76% меньше), p95 малых запросов 227739 → 231873 мкс (+1,8%). Критерий минимум 15% улучшения и не более 5% ухудшения p95 выполнен. Проценты не переносятся на YouTube.

Принято только для AWG fallback TCP: приём 2 МиБ, отправка, ACK delay, reassembly segments и congestion неизменны. Дополнительный бюджет памяти остаётся 64 МиБ на сессию; при недостатке разрешений окно уменьшается до 512 КиБ, затем 128 КиБ. Разрешение возвращается при отмене/закрытии. Idle-соединения могут занимать бюджет; реальный выбранный размер виден в TUNNEL_TCP_SOCKET_METRICS. Обычный WireGuard, Reality, Hysteria2 и прямой Windows TCP не получают увеличенного окна. Нет изменений MTU, сервера, DNS профиля или обфускации.

Отдельная проверка на RTT 100 мс / 0,5%: целостность 64 МиБ, 8 параллельных малых запросов, отмена старой загрузки и новый запрос после паузы. Передача 64 МиБ 15,792350 с; новый запрос 1 МиБ 1,706452 с; повреждений/зависаний нет.

Воспроизведён независимый дефект: IPv4 с корректными опциями (например Router Alert), не являющийся фрагментом, отвергался в Reassembly как fragment_invalid. Теперь пакет передаётся без изменения. Фрагменты IPv4 с опциями остаются явно неподдерживаемыми; лимиты сборки прежние. Причины fragment_invalid, fragment_unsupported и fragment_capacity разделены. Не утверждается, что именно такие пакеты составляли 15 отказов пользователя или тормозили видео.

Маршрутные наблюдения теперь сообщают missing/expired/overflow/observed, число имён и оставшийся TTL. TTL не продлевается, записи не выдумываются, неоднозначные DIRECT/REJECT сохраняются. Opt-in RESOURCE события включают TTL, первый байт и агрегированный прогресс прямого пути. resources.jsonl ограничен 256 КиБ на запуск, содержит только allowlisted метаданные и не растёт бесконечно. По достижении лимита остаётся начало отчёта. Полные TLS/HTTP данные и URL не записываются.

Проверки: names 5, DNS 15, router 13, fragments 3, TCP budgets 2, tunnel_outbound 4, packet routing 6, TUN relay 2 (группы пересекаются); .NET diagnostics 3; два локальных AWG стенда.
