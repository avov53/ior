# Windows 1.2.6 — тестовая сборка

Не опубликована. Android и dist не менялись. Рабочая 1.2.5 сохранена.

Изменения:
- При проверке NRPT считаются только записи с непустой областью действия.
  Пустые служебные объекты не блокируют запуск. Реальные правила, включая
  корневое `.`, продолжают блокировать замену DNS; чужие правила не удаляются.
- До проверки DNS ior-core сохраняет `%APPDATA%/ior/dns-policy-report.json`.
  В нём есть подробности правил для определения происхождения конфликта.
  Если конфликт реальный, можно вручную проверить Proxy для VLESS/Hysteria2.
- Локальный SOCKS outbound DIRECT Xray явно привязан к IPv4 loopback,
  соответствующему адресу собственного помощника. Это исправление кандидата
  для ошибки `[::] -> 127.0.0.1`; результат на проблемном ПК пока не подтверждён.
- Ошибки обнаружения TUN включают Windows, имена/ID/состояния принадлежащих
  ior адаптеров. Ошибки проб сохраняют типы обеих попыток, включая socket-код.
- Информационный Xray HTTP EOF больше не помечается как ошибка в WebUI.

## Сотруднику

1. Распаковать полный Windows 10 ZIP в новую папку. Закрыть прежний ior,
   запустить новую копию обычным способом с запросом прав администратора.
2. Проверить VLESS Reality и Hysteria2 на ior-core, затем xray-core в TUN.
   AWG проверять только с ior-core TUN. Записать время каждого запуска.
3. Проверить отключение, повторное подключение, отмену запуска, смену сети.
   При ошибке не удалять системные DNS-политики и не отключать проверки готовности.
4. Скопировать журнал приложения. Запустить из папки сборки:
   `powershell -NoProfile -ExecutionPolicy Bypass -File .\Collect-WindowsDiagnostics.ps1`
   Скрипт только читает сеть и создаёт локальный `diagnostics-local/windows-network.json`.
5. Отчёты DNS могут содержать внутренние имена организации: просмотреть их
   перед добровольной передачей. Конфиги, ссылки подписок, ключи и пароли не нужны.

игнорируются, корневые и доменные правила сохраняются как конфликт.

таймауты к частному адресу. Автоматические исключения частных сетей и изменения

сети и первоначальная причина NRPT пока требуют проверки по инструкции выше.
