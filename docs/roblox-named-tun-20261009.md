# Roblox: подтверждённое имя для потокового PROXY в TUN

## Данные и воспроизведение

Скриншот показывает незагруженные превью. Приложенный журнал — Xray; выбранный
контроль по уточнению пользователя Hysteria2, изображения там появлялись, вход
в плейс не подтвердился. Ранее предположение о VLESS было ошибочным: Xray в
этой версии поддерживает Hysteria2. Локальный журнал ior 18:52 относится к AWG,
поэтому сравнение этих двух запусков не изолирует один протокол/сервер.

На текущем выбранном Hysteria2-профиле отдельно запущен локальный Proxy ior-core,
без TUN/системных маршрутов и без cookies. Публичный запрос миниатюры по имени
вернул HTTP 200, изображение tr.rbxcdn.com — 200, ~15 КиБ. В варианте с локальным
разрешением IPv4 API вернул 200, но разрешение имени CDN закончилось HostNotFound;
IPv6-вариант завершился I/O-ошибкой (её источник по этому результату не установлен).
Это подтверждает различие локального и серверного адресного пути, но не полное
воспроизведение картинки конкретного пользователя в TUN.

По официальному API дополнительно получена публичная PNG-иконка плейса
Murder Mystery 2: API и CDN HTTP 200, HTTP/2, 8212 байт, PNG-сигнатура верна.
Не использовались аккаунт/cookies, не сохранялись подписанные URL или ключи.
Документация: https://prod.docsiteassets.roblox.com/assets/en-us/cloud/legacy/thumbnails/v1.json

## Исправление

- После достоверного HTTP Host/TLS SNI TUN раньше всегда передавал исходный IP
  поточному PROXY. Теперь Hysteria2, VLESS TLS/Reality, VMess, Trojan и Shadowsocks
  получают подтверждённое имя, которое разрешается на сервере выхода.
- Решение маршрутизации сначала принимается по исходному IP и имени, в прежнем
  порядке правил. Только выбранный PROXY может использовать имя; DIRECT сохраняет
  исходный адрес, REJECT не обходится. Установленные соединения не переключаются.
- Одного DNS-наблюдения без HTTP/SNI недостаточно для замены назначения.
  ECH/его GREASE-представление консервативно сохраняет исходный IP: внешний cover-SNI
  не принимается за адрес сайта. Проверены фрагментированный ClientHello и ECH
  после SNI; TLS/DNS-ответы не переписываются.
- IP-туннели AWG/WireGuard явно исключены. Их пакетный путь, DNS профиля, окно
  512 КиБ, бюджет 64 МиБ, MTU и обфускация не менялись. Roblox на AWG этой правкой
  не объявляется исправленным; его диагностический сценарий остаётся доступным.
- Журнал TUN_PROXY_NAMED_DESTINATION показывает применение нового пути.
  Обязательных полей состояния/контракта и изменений сервера нет.

## Проверки и выдача

10 проверок native_router (включая 2 новые), 2 TUN, 16 AWG, 8 VLESS, 6 остальных
нативных протоколов и отдельная проверка ClientHello/ECH прошли. Группы пересекаются.
Три opt-in HTTP-прогона дали санитизированные результаты; основной результат
публичной PNG проверен assertion. Опт-ин тест использует только выбранный профиль,
не изменяет state.json, не создаёт Wintun и не является браузерной автоматизацией.
Release Rust и Windows 10/11 publish прошли. Живые TUN/Roblox и Windows 10 требуют
проверки пользователя. Ни все приватные ресурсы, ни вход в плейс не подтверждены.

Пакеты в awg-current/windows-11 и windows-10. Закрыть прежний ior, запустить полный
каталог, переподключить Hysteria2 + ior-core + TUN; проверить те же превью и игру.
Если изображения остаются пустыми, использовать Start-RobloxDiagnostics.cmd и
журнал сразу после сбоя, включая домен/HTTP-ошибку из Network браузера.
Сохранённые быстрые архивы AWG проверены и не перезаписывались; временные файлы
и кеши очищены. dist.bat не запускался, dist и пользовательские данные сохранены.

## Предупреждение сборки

NU1900 на скриншоте относится к недоступности данных об уязвимостях NuGet,
а не к ошибке компиляции. Сборка завершилась успешно, но аудит зависимостей тогда
не завершился. Предупреждение не скрывалось отключением аудита.
Источник: https://learn.microsoft.com/en-us/nuget/reference/errors-and-warnings/nu1900
